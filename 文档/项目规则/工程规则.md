# 工程规则

最后人工/AI 更新：26-06-10-0000

本文定义留素长期工程红线。更细的尺寸、边框、缓存、UI 和测试规则见同目录专题文档。

## 五个工程底线

### 1. 性能底线

不能用奢侈的解码、重绘、内存分配、全量刷新或重复导出计算换取表面实现。

重点路径：

- 图片导入和缩略图生成。
- 模板切换。
- 槽位拖拽、缩放、旋转、裁切偏移。
- 页面预览重绘。
- 边框叠加。
- 批量导出。

这些路径必须优先考虑缓存、节流、短路、增量更新、后台任务边界和内存峰值。

### 2. 功能底线

本轮目标功能必须真的可用。修复或更新时不能破坏：

- 既有项目文件读取。
- 二 / 四 / 九模板行为。
- 图片槽位编辑状态。
- 预览与导出一致性。
- 边框叠加顺序。
- 缓存命中和失效。
- 导出质量和物理尺寸口径。

### 3. 注释底线

关键位置必须写关键注释，说明契约、边界、原因或未来 AI 容易误改的点；禁止为了注释数量写装饰性废话。

重点注释位置：

- 相纸物理尺寸和 PPI 换算。
- mm / px / normalized rect 坐标转换。
- 模板槽位生成。
- 图片 EXIF 方向处理。
- 填充、裁切偏移、旋转、镜像顺序。
- 边框孔位和绘制层级。
- 缓存 key 组成和失效策略。
- 预览、缩略图、导出共用渲染入口。

### 4. 指令底线

用户指令优先，但不是无条件执行。遇到以下要求时，必须先说明风险、替代方案和取舍：

- 改相纸物理尺寸或默认 PPI。
- 改导出像素计算。
- 改项目文件格式且没有迁移策略。
- 改缓存 key 且没有旧缓存失效策略。
- 把胶片尺孔硬编码进某个模板。
- 让 QML 页面决定最终导出几何。
- 从旧参考项目复制大段代码。
- 把多个职责合并进一个巨型控制器或服务。

普通小不确定性由 AI 按现有规则保守处理，并在最终回复或文档中记录假设。

### 5. 职责边界底线

新功能必须按职责 / 功能边界拆成独立模块。公共底座只承载共享原语、稳定契约和薄路由。

禁止：

- 把导出算法写进 QML。
- 把边框系统写死在模板函数里。
- 把缓存策略散落在 UI 控件里。
- 把图片读取、布局、渲染、导出、项目保存全部塞进一个控制器。
- 把所有功能测试塞进一个巨型测试文件。

推荐职责分层：

```text
Domain / Model：页面、槽位、图片状态、边框规格、项目文件数据结构。
Layout：模板槽位和页面几何。
Render：预览、缩略图、导出共用渲染管线。
Image：图片读取、EXIF、变换、缓存。
Border：胶片尺孔、白边、拍立得边等边框规格和绘制。
Export：导出参数、PPI、文件写入、打印前检查。
UI：QML 页面、交互、视觉状态、命令入口。
Tests：尺寸、渲染、缓存、项目文件、UI 绑定的独立测试。
```

## 默认技术边界

- 首选 Qt 6 + C++17 + QML，除非用户明确重新选型。
- UI 层只能调用清晰的应用服务或命令接口，不能直接改底层渲染细节。
- 领域模型应可序列化、可测试、可回放。
- 导出不能依赖当前屏幕缩放、窗口大小或 QML 可见项实际尺寸。
- 所有新规则要能被测试、样张或审计尽量验证。
