# 大任务基准与子方案拆分法

最后人工/AI 更新：26-06-10-1727

本文记录一种适合留素重写阶段的 AI 协作方法：把大任务先整理成一个稳定基准文档，再拆成多个只做一小块的子方案。目标是防止上下文爆炸、任务错位、AI 自行外扩，同时让每一步都更容易验收、回滚和交接。

本文是经验笔记，不是当前事实来源，也不是硬工程规则。具体任务仍以用户最新指令、当前源码、最近更新记录和对应计划文档为准。

## 适用场景

适合使用本方法的任务：

- 涉及多个模块，例如 UI、布局、渲染、缓存、导出、项目文件。
- 历史参考较多，旧项目、旧方案和当前目标容易混淆。
- 一次性让 AI 完整实现会造成上下文过长，后半段容易忘记前半段约束。
- 需要多会话接力执行。
- 用户希望先充分讨论和定界，再按小步实现、验证和收口。

不适合使用本方法的任务：

- 单文件小修、小文案调整或一次命令能完成的简单任务。
- 需求还很模糊，连目标和范围都没有确定的早期讨论。
- 每个步骤高度互相依赖且无法拆出清晰验收点的短任务。

## 推荐结构

```text
文档/当前在做计划/<计划名>/
  00-基准.md
  01-子方案一.md
  02-子方案二.md
  03-子方案三.md
  04-验证与收口.md
```

`00-基准.md` 只放所有子方案必须共同遵守的锚点：

- 用户原始目标和最新取舍。
- 明确范围。
- 明确不做什么。
- 当前已知源码入口或参考入口。
- 必须保护的既有功能。
- 性能、功能、注释、指令、职责边界等底线。
- 最终验收口径。

子方案只放当前小步骤要做的事：

- 开头必须要求先读 `00-基准.md`。
- 明确写“本会话只执行本子方案，不外扩到其它子方案”。
- 写清前置条件。
- 写清本方案范围。
- 写清禁止事项。
- 写清验收方法。
- 写清后续衔接。

最终收口方案只做整体验证、文档更新、交付准备和计划归档，不再临时塞新功能。

## 执行流程

1. 先讨论目标、范围和非范围。
2. 写 `00-基准.md`，确认基准是否准确。
3. 把实现拆成多个小子方案，每个子方案只覆盖一个可验收动作。
4. 每次开新会话时，只发当前子方案和一条短 prompt。
5. 当前会话先读基准，再执行当前子方案。
6. 每个子方案完成后说明改动、验证结果和下一步。
7. 全部实现完成后，再执行最终收口方案做整体验证、文档更新和交付。

## 子方案模板

```text
# 01-示例子方案

最后人工/AI 更新：yy-MM-dd-HHmm

开始前必须先读取同目录的 `00-基准.md`。本会话只执行本子方案，不外扩到其它子方案。

## 承接状态

- 前面已经完成：无 / 说明上一方案应留下的状态。
- 本方案负责：只写当前小块。
- 后续计划：完成后交给 `02-...md`。

## 当前范围

- 要做什么。
- 只允许触碰哪些文件、模块或行为。

## 明确不做

- 不做相邻功能。
- 不提前做后续子方案。
- 不把讨论假设写成已实现事实。

## 实施步骤

1. 读取必要源码和文档。
2. 做最小改动。
3. 增加或调整必要测试。
4. 按任务风险运行验证。

## 验收

- 行为验收。
- 构建 / 测试 / 审计。
- 用户需要复测的点。
```

## 推荐短 prompt

执行某个子方案时，可以使用：

```text
请执行 <项目根目录>/文档/当前在做计划/<计划名>/<子方案文件>.md。本会话只执行这一个子方案；开始前必须先读取同目录的 00-基准.md，并严格遵守其中的范围、五个工程底线和“不影响既有功能”要求。不要外扩到其它子方案，也不要修改未列入范围的功能。完成后说明改动、验证结果和下一步应交给哪个子方案。
```

让 AI 先生成整套计划时，可以使用：

```text
请先不要改代码。把这个大任务整理成 <项目根目录>/文档/当前在做计划/<计划名>/ 下的一套计划文档：一个 00-基准.md，若干个只覆盖一小块的子方案，以及一个最终验证与收口方案。每个子方案开头都必须要求先读 00-基准.md，并写明本会话只执行本子方案，不外扩到其它子方案；每个子方案还要包含承上启下信息、当前范围、明确不做、实施步骤和验收方法。完成后补更新记录。
```

## 风险和防护

### 风险：拆得太碎，整体闭环丢失

防护方式：保留最终验证与收口方案；每个子方案写下一步；基准文档写最终验收口径。

### 风险：基准文档变成第二个大上下文包袱

防护方式：基准只写硬约束、范围、非范围、入口和验收；详细实现放入对应子方案。

### 风险：子方案之间状态漂移

防护方式：每个子方案写前置条件和承接状态；执行前用源码、测试和当前计划文件确认前置是否真的完成。

### 风险：AI 看到相邻代码后顺手外扩

防护方式：子方案开头写明“本会话只执行本子方案”；明确列出不做内容；最终回复说明是否触碰了非范围文件或行为。

### 风险：计划文档过期

防护方式：计划完成、失败、废弃或被新路线替代后，移入 `文档/归档历史计划/`；不要让旧计划长期留在 `当前在做计划/`。
