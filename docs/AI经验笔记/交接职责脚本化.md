# 交接职责脚本化

本文是经验笔记，不是当前事实来源，也不是硬工程规则。正式规则以 `AGENTS.md` 和 `docs/规范/` 为准。

## 经验

当一个仓库长期依赖多个入口文档交接时，只靠文字约定很容易重新长出第二份“当前状态”。即使当时明确了唯一冷启动入口和唯一动态事实载体，后续会话仍可能把废弃入口重建回来。

## 做法

- 先明确唯一冷启动入口（当前为根 `AGENTS.md` → `docs/README.md`）。
- 再明确动态事实的唯一载体（当前为仓库 Issues）。
- 入口职责调整时，同一任务同步更新 `AGENTS.md` 路由、`docs/README.md` 和[文档治理规则](../规范/文档治理规则.md)，不留旧入口的影子。
- 如果项目有健康检查脚本，脚本要同时检查废弃入口不存在、新入口存在。

## 适用边界

适用于文档体系、计划体系等“入口职责”调整。不适合用来替代功能设计、代码验证或用户实测。
