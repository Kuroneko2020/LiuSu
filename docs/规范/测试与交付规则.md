# 测试与交付规则

本文规定 AI 修改留素项目后的测试、记录和交付纪律。

## 文档-only 任务

只改 Markdown、计划、规则或说明时：

- 不需要构建。
- 不需要生成测试包。
- 需要检查目录、链接、术语和是否误搬其它项目内容。
- 把变更提交进 Git，提交说明写清本轮范围；文档体系或规则结构变化按[文档治理规则](文档治理规则.md)处理，必要时新增 ADR。
- 最终回复说明本轮只整理文档。

## 源码任务

改源码后必须至少：

- 运行项目构建命令。
- 说明构建命令和结果。
- 根据风险运行相关测试。
- 提交 Git，提交说明写清改动与验证结果。
- 如果无法测试，说明原因和剩余风险。

## 高风险任务加测

涉及以下内容时，需要优先补测试或样张验证：

- 相纸尺寸、PPI、导出像素尺寸。
- 模板槽位坐标。
- 图片 EXIF 方向。
- 旋转、镜像、裁切偏移。
- 胶片尺孔或其它边框。
- 缓存 key 和缓存失效。
- 项目文件格式或迁移。
- UI 与导出状态同步。

## 样张验证

导出类功能推荐保留固定输入图片和固定项目文件，用来生成可比对样张。样张验证至少检查：

- 输出像素尺寸。
- 槽位数量和位置。
- 图片方向。
- 边框孔位和层级。
- 背景。
- 裁切辅助线是否按设置出现。

## 记录要求

- 代码、脚本、项目文件变更：Git 提交，提交说明写清改动、验证结果和剩余风险。
- 动态进度、阻塞、授权变化：更新对应仓库 Issue；Issue 体系建立前，在最终回复中明确说明。
- 文档体系或规则变更：按[文档治理规则](文档治理规则.md)，必要时新增 ADR。
- 发现高价值经验：写 [AI经验笔记](../AI经验笔记/索引.md) 对应主题。

## 交付口径

最终回复至少说明：

- 改了什么。
- 哪些文件受影响。
- 运行了什么验证。
- 没运行什么验证以及原因。
- 用户下一步应复测什么。
