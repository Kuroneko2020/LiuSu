# ADR-0002：文档体系迁移与 R 式治理

- 状态：Accepted
- 日期：2026-10-07

## 背景

留素早期文档体系复制自决明-Z 早期的 AI 协作模型：文档作为本地协作材料不进仓库，用 append-only 更新记录做交接账本，配多层计划目录和文档元规则。决明-R 在其 [ADR-0001](https://github.com/Kuroneko2020/JueMingR/blob/main/docs/决策/ADR-0001-文档体系与受控演进.md)（2026-08-28）中对该模型做了代表性调查，指出五个主要问题：

- 正式规则和文档没有与代码共同进入 Git；
- 当前事实分散在多个计划、索引、状态和记录中；
- 更新记录、文档更改历史和归档计划持续膨胀；
- Agent 冷启动需要经过过长的文档链条；
- 文档审计和治理本身成为工程负担。

所有者于 2026-10-07 决定：留素采用 Git 版本管理优先，结构与方法向决明-R 的文档治理看齐，并授权按留素的规模裁剪实施。留素尚无源码，迁移成本处于最低点。

## 决策

1. 文档与代码共同进入 Git。根 `AGENTS.md`、根 `README.md` 和 `docs/` 下的正式文档是仓库的正式跟踪内容；变更历史由 Git 提交承担。
2. 原 `文档/` 目录迁移为 `docs/`。根目录名保持英文，`docs` 下的目录与文件名使用中文。
3. 动态任务状态以仓库 Issues 为唯一权威载体；规范、决策和未来计划不复制 Issue 状态。
4. 不再建立更新记录目录、文档更改历史目录和全量计划归档。原 `文档/更新记录/` 的两条历史记录（0001 文档与架构基线、0002 文档系统收缩）随基线提交进入 Git 历史后从工作区删除，其实质内容已被本 ADR 和新结构覆盖。
5. 首批建立 `docs/规范/`、`docs/决策/`、`docs/AI经验笔记/`；`设计/`、`计划/` 只在出现真实文档职责后经所有者批准并通过 ADR 建立，不预建空目录。
6. `references/`（旧留素只读参考）保留在本地并加入 `.gitignore`；使用边界由[文档治理规则](../规范/文档治理规则.md)承载，替代原 `文档/文档规则/参考资料隔离规则.md`。（本条所指的旧留素参考已按 [ADR-0012](ADR-0012-删除旧留素项目快照.md) 删除；`references/` 现仅剩外部美术参考，仍为只读。）
7. 原 `文档/文档规则/`（目录、书写规范）的职责收敛到[文档治理规则](../规范/文档治理规则.md)；“最后人工/AI 更新”页眉取消，变更时间线由 Git 承担。
8. 五个工程底线和各领域规则（尺寸渲染、边框模板、图片缓存、UI、测试交付）的实质内容原样保留，只调整位置、交叉引用和记录载体；原 `文档/项目规则/` 内容迁入 `docs/规范/`，原 `文档/AI经验笔记/` 的两篇方法笔记迁入 `docs/AI经验笔记/`。
9. 原 `文档/产品定义.md` 的内容迁入根 `README.md`；原 `文档/冷启动说明.md` 的职责并入本文件路由和 [docs/README.md](../README.md) 冷启动说明。

## 结果

好处：

- 规则、决策与后续代码可共同追溯；
- 动态状态只有一个权威载体，减少多账本同步；
- 冷启动路由更短，历史材料不再自动进入默认读取路径；
- 目录可以在出现真实职责时演进，不被首版结构锁定。

代价：

- 历史追溯依赖 Git 与 Issues 而不是本地账本；
- Issues 体系建立前，动态状态暂由 docs/README.md 状态段临时代替；
- 一级结构调整需要所有者批准和 ADR，产生少量决策成本。

## 被替代方式

本 ADR 生效后，原 `文档/` 体系的冷启动顺序、更新记录账本、文档元规则和计划归档机制全部废止，旧结构由基线提交保留在 Git 历史中。若未来事实证明其他组织方式更合适，应创建新的 Accepted ADR 明确替代范围与迁移方式，并将本 ADR 状态改为 `Superseded`；不得静默改写本决策。
