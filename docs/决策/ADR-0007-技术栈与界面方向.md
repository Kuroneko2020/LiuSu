# ADR-0007：技术栈与界面方向

- 状态：Accepted
- 日期：2026-10-07

## 背景

所有者将剩余第一阶段细节决定委托给 AI（2026-10-07）。其中最重要的委托项是技术栈：旧版采用 Qt 6 + C++17 + QML，所有者的原始诉求是"干净、丝滑、灵动、高级"的界面效果，同时自评旧版"设计感很差"、自认不了解开发。

需要判断：换技术栈还是维持 Qt；如何避免旧版"设计感差"的问题重演。

## 决策

1. 维持 Qt 6 + C++17 + QML 作为留素技术栈。QML 的声明式 UI 与 GPU 加速渲染正是"丝滑、灵动"类效果的低成本路径；桌面照片工具的渲染需求（高分辨率位图、缩放平移、动画）与 QML 能力匹配。旧版的问题出在界面设计，不是框架，换框架不能解决设计感。
2. 界面采用"设计稿先行"流程：编码前先产出 2–3 版视觉风格稿（布局密度、配色、控件形态、动效倾向），由所有者选定后再实现 QML 界面。界面实现以选定的风格稿为验收参照。
3. 界面视觉目标记录为：干净、丝滑、灵动、高级。旧版 UI 仅作反例与行为参考。
4. [工程规则](../规范/工程规则.md)的职责分层、QML 边界等条款继续适用；设计稿只约束视觉与交互形态，不改变"QML 不是几何真相来源"的架构边界。

## 结果

好处：

- 不为重写而重写，直接进入有效产出。
- 设计与实现解耦：所有者在早期就能看到并选定外观方向，避免"做完才发现不好看"。
- C++ 侧承载渲染与图片处理的性能底线有保障。

代价：

- Qt + QML 的开发生态以 C++/QML 技能为基础，AI 实施时需注意 Qt 6 版本的 API 差异。
- 设计稿先行增加一步流程，但换来低返工风险。

## 被替代方式

若未来事实证明 Qt 6 + QML 不满足需求（如遇到不可绕开的平台限制），应创建新的 Accepted ADR 说明替代技术栈与迁移方式，并将本 ADR 状态改为 `Superseded`。
