# ADR-0014：空间交互与可扩展目录

- 状态：Accepted
- 日期：2026-10-08
- 关系：修正 ADR-0013 的美术表达及模板身份口径；逐页模板与照片保全规则继续有效。

## 所有者决定

所有者指出新照片工作台仍然平，所需的不是莱茵生命的颜色和线条，而是立体、灵动、有生命的互动感；选择更强的舞台感，允许鲜明倾转与展开。同时明确当前导出设置仅为一部分、四个基础模板仅为起点，不能把它们写死为产品边界。此前直接授权继续有效，新观感仍须所有者验收。

随后所有者进一步明确中央实际编辑位应收敛，避免影响操作。因此模板展示仍采用强空间互动，中央编辑纸面以稳定正视与直接命中为先。

## 决策

1. 模板是空间中的实体展示板：分离台面投影、板面、厚度与反光；指针位置驱动倾转，靠近时抬起，离开时带阻尼落定。静止时不持续运行动画。页队列与工具按键使用相同空间反馈的较小力度。
2. 中央编辑纸面始终正视且位置固定，去除进入编辑与换页的倾转、抬升及动态投影。只留薄边、轻柔静态阴影与 140ms 的轻微图像明度反馈；反馈不变换命中区域，按下照片立即结束。裁切增量使用稳定工作区坐标。所有空间表达仅为 UI，不改变导出几何。
3. 模板目录由领域层统一提供身份、名称、分类、说明与实际槽位；首页可搜索、横向滚动，编辑入口打开可搜索且按需生成的模板库。卡片宽度、英文说明、数量和添加页入口不得依赖四个基础模板。
4. 外部模板以 JSON 目录导入。一个包完整校验后加入，重复 ID 或任一无效槽位拒绝整个包。服务层用原子文件保存输入快照到应用数据目录的 `templates/`，下次启动自动加载，来源文件移动不影响已导入模板。不修改只读 `references/`。
5. `ProjectPage` 在 v1 JSON 中增加可选 `templateId`。旧项目字段缺失仍可读取；槽位几何继续完整保存，不依赖目录重建。目录缺失时身份保留，名称显示自定义模板，页面仍可重开、编辑与导出。同布局不同身份不会被误认成同一模板。
6. 导出 UI 按能力定义的类型、标签、范围、预设、可见条件与高级标记生成控件，定义保留分组元数据供后续组织使用。当前实现 JPEG/PNG、PPI 和 JPEG 质量；这些是当前能力而非最终清单。新增输出能力需同时实现领域/服务处理、持久化和测试，再注册定义，不能靠新增控件宣称支持。未知选项或无效参数拒绝，不污染已有设置。

## 目录格式与边界

```json
{
  "templates": [{
    "id": "triptych",
    "name": "三联",
    "category": "留存",
    "caption": "TRIPTYCH",
    "slots": [
      {"x": 0, "y": 0, "width": 0.3, "height": 1},
      {"x": 0.35, "y": 0, "width": 0.3, "height": 1},
      {"x": 0.7, "y": 0, "width": 0.3, "height": 1}
    ]
  }]
}
```

ID 使用字母、数字、点、连字符或下划线，首字符为字母或数字，最长 128 字符且在目录中唯一。名称必填；分类、说明可省略。坐标为页面归一化数值，矩形必须有效且落在页面内；可共边，不能面积重叠，避免照片被遮住却无法选择。层叠照片需要另行实现层级编辑后扩展。此入口只负责槽位模板，不把边框、打印机档案或自由布局编辑一并宣称为已实现。

模板导入会校验并持久化整个包；暂不提供目录卸载、同 ID 更新或模板编辑器。导出扩展保留既有相纸尺寸、PPI 校验和共享渲染合同。自动 Qt 输入与实际 QML 渲染证据不能替代所有者的桌面手感验收及实际打印。
