# ADR-0003：页面与打印机档案化，尺寸不写死

- 状态：Accepted
- 日期：2026-10-07

## 背景

所有者明确：当前主要应对 6 英寸照片打印机排版，但未来需求不定，尺寸不能写死。所有者的打印机型为小米米家照片打印机 1S。所有者还提出未来的尺寸校准设想：软件生成校准矩形，打印后由用户输入实测尺寸，软件计算偏移并按打印机保存。

旧版把尺寸确认绑定在单一默认值上（`148mm × 100mm` 是否沿用长期悬而未决），没有承载"未来可能换尺寸、换机器"的模型位置。

## 决策

1. 页面尺寸模型不写死单一数值。6 英寸相纸是首个页面档案；未来支持其它尺寸时新增档案，不改写核心模型。
2. 引入打印机档案：每台机型一条档案，承载可打印区域、留白、推荐输出密度等参数。档案可新增、可修改，不属于代码常量。
3. 首个打印机档案的目标机型为小米米家照片打印机 1S：热升华打印，输出密度 300 dpi，6 英寸相纸 `100mm × 148mm`；可打印区域与留白的毫米级数值以官方手册或实测核定后写入档案，不得凭搜索摘要直接当事实。
4. 预留尺寸校准机制（第一阶段不实现）：校准矩形输出 → 用户打印实测 → 软件计算尺寸偏移 → 偏移保存到对应打印机档案。页面与导出模型需预留该偏移的输入位置，但第一阶段不实现校准 UI 与计算。
5. "相纸物理尺寸只能由统一配置或统一函数提供"的原则不变，档案即该统一来源的数据形态。

## 结果

好处：

- 未来换相纸尺寸或机型只加档案，不动渲染与导出核心。
- 校准机制有明确的模型归属（打印机档案），不会散落在 UI 里。
- 300 dpi 输出密度与热升华机型匹配，避免盲目高倍导出。

代价：

- 页面模型多一层档案抽象，第一阶段需以最小形式实现（至少：页面尺寸 + 推荐密度来自档案对象，而非散落常量）。
- 档案数值的核定责任（官方手册或实测）需要有人执行并记录来源。

## 被替代方式

若未来证明档案化设计不合适（例如所有机型参数可穷举），应创建新的 Accepted ADR 明确替代范围与迁移方式，并将本 ADR 状态改为 `Superseded`。
