# ADR-0008：第一阶段实施细节与开发顺序

- 状态：Accepted
- 日期：2026-10-07

## 背景

所有者对开发顺序和剩余第一阶段细节没有倾向，明确委托 AI 决定（2026-10-07）。本 ADR 记录决定结果，并授权建立实施计划目录 `docs/计划/`（文档体系首个计划，结构演进依据见 [ADR-0002](ADR-0002-文档体系迁移与R式治理.md)）。

## 决策

第一阶段实施细节：

1. 布局预设首批名单：单张全幅、二、四、九（承载于通用布局模型，见 [ADR-0006](ADR-0006-产品定位与布局泛化.md)）。各预设的具体几何在实施时参照实物效果与旧版行为确定，用样张验证。
2. 背景：首版纯色背景，默认白色，颜色可自选；花纹 / 图片背景属于未来方向。
3. 导出格式：JPEG（质量可调）与 PNG，与旧版一致；原图导出模式（自动 PNG、忽略 PPI）一并沿用。
4. UI 走"设计稿先行"流程（[ADR-0007](ADR-0007-技术栈与界面方向.md)）。
5. 技术栈 Qt 6 + C++17 + QML（[ADR-0007](ADR-0007-技术栈与界面方向.md)）。

开发顺序（为什么这样排）：

1. **骨架 → 领域模型 → 图片缓存 → 渲染管线 → 界面 → 收口**。先做"看不见但决定一切"的核心：尺寸档案、布局模型、渲染同源、缓存。这些用单元测试和固定样张锁住之后，界面只是把已验证的核心套上外壳——这样"丝滑、高级"的界面不会破坏导出正确性。
2. **界面设计稿并行提前**：风格稿不依赖代码，从领域模型阶段就同步推进，所有者尽早选定方向。
3. **渲染先于界面**：渲染管线用测试和样张验收，不依赖界面存在；界面对接它时不再改几何逻辑。
4. **导出与项目保存放在收口段**：导出像素计算在渲染段已验证，收口段只做设置交互与全流程串通。

## 结果

好处：

- 每一步有独立可验收产物，适合多会话接力（[大任务基准与子方案拆分法](../AI经验笔记/大任务基准与子方案拆分法.md)）。
- 高风险项（尺寸换算、渲染同源、缓存 key）最早被测试覆盖。
- 所有者在第一周末尾即可看到选定风格的界面雏形与真实导出样张。

代价：

- 前期以测试和模型为主，可见进展偏"内部"，需要所有者接受前几步没有可玩界面。

## 被替代方式

实施计划完成或方向变化时，按文档治理规则收尾；若顺序本身需要推翻，创建新的 Accepted ADR 说明理由与调整。
